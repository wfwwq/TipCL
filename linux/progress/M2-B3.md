# M2-B3 · 下载页 + 安装页

## 做了什么

按 R2 侦察报告（docs/m2-recon/R2-download-install.md）移植 Windows 版 `DownloadPage.cs`（265 行）与 `InstallPage.cs`（compact 分支，PREMIUM 不做）到 Avalonia，视觉对齐 `docs/mockups-hark/v2/download2.png` / `install2.png`。

### 下载页 `src/TipCL.App/Pages/Download/DownloadPage.cs`
- 顶部灰色轨道 7 段分段（Seg.Rail / Seg.Item，原版/Mod/整合包/数据包/资源包/光影/世界）；右上「任务 N」按钮 + 数字角标（TaskStore.RunningCount，Added/Finished 事件经 Dispatcher 联动），点击 Navigate("tasks")。
- 原版分段：搜索框 + 正式版/快照/远古三段筛选（Ghost/Soft+Bold 切换）+ 版本列表卡。列表行高 46、列宽 130/*/110/Auto、首行无顶分隔线、行 hover 背景 B.RowHover + 行尾「安装」按钮 Soft→Primary 换肤（PointerEntered/Exited）。最新 release / 最新前一条 snapshot 的 Tag 用 B.AccentText/B.AccentSoft 高亮。
- 版本清单两段式加载：`get_version_list`（缓存）先渲染 → `fetch_version_list`（9s 超时，FetchTimeoutMs=9000 静态可调）远程刷新覆盖；远程失败且本地为空 Toast「版本清单刷新失败」。`ParseVersionRows` 复刻 Windows `_version_rows` 语义（type 归并 / 日期取前 10 位 / 按日期倒序）。
- Mod..世界 6 分段：CatalogPage 属目录工作包（R3），暂放统一 Empty 占位，接口已留（ShowSeg 懒挂位）。
- 「安装」→ `OpenInstall(row)` 整页切 InstallPage 子视图，返回回调恢复。

### 安装页 `src/TipCL.App/Pages/Install/InstallPage.cs`
- 5 张加载器卡（不安装/Fabric/Forge/NeoForge/Quilt）：官方图标 Tile 36×36 圆角 9、选中 B.Accent 描边 + B.AccentTint 底 + 右上勾角标、探测无货禁卡 Opacity 0.45 + 副文本「不支持此版本」。
- 加载器版本探测 6 请求并发（fabric/forge/neoforge/quilt/optifine/liteloader × mc 版本，`list_loader_versions`）；版本下拉仅选中卡显示，推荐项（首个 Stable 否则 [0]）尾缀「· 推荐」，空列表兜底「最新」。
- Fabric API 开关：仅 Fabric/Quilt 显示且自动勾上；OptiFine 开关：仅 不安装/Forge 且探测有货可用，否则置灰 + 原因文案（无货 / 与加载器不兼容提示 Sodium + Iris）；LiteLoader 行仅探测有货时显示（老版本）。
- 实例名自动命名（卡 0=版本号，否则「{加载器} {版本}」），用户手改后不再覆盖（对照 _lastAutoName 实现）；右内 hint「装入已有实例 / 将新建实例」（get_instances 名字表）。
- 底部固定栏：B.GlassStrong + 顶 1px RowLine；「将安装 X + Y + Z · 约 N MB」体积估算表 Mb=[30,1,15,15,2]、Fabric API +2、OptiFine +7、LiteLoader +1；「开始安装」Btn.Primary。
- 安装流（I8）：名为空 Toast；名字不存在先 `create_instance`；`StartTaskAsync("安装游戏 …")` 入 TaskStore 队列，work 内调 `install_game`（extra: optifine/liteloader），并把 install_game 经 BridgeEvent 冒泡的 progress/log 泵进 TaskProgress（B0 的 install_game 走 CallCore 只发事件）；Fabric API 勾选时主任务成功后追加独立任务「安装模组 Fabric API」直调 `Mods.InstallModrinthMod(dm, "fabric-api", …)`（B0 的 install_mod 方法表走 urls/url 契约，故绕过直调 Core 等价实现）；随后 Toast「已加入队列」+ Navigate("tasks")（FlyToTasks 降级为直接跳转，R2 §2.3）；期间按钮禁用，异常 Toast「安装失败」。

### 加载器图标 `src/TipCL.App/Pages/Download/LoaderIcons.cs`
- 采 R2 §3 建议的嵌入路线：5 张官方图（grass/fabric_gh/forge_gh/neoforge_gh/quilt.svg，约 23KB）转 64px PNG 后 base64 内嵌为 `const string`（免改 csproj 资源项，规避依赖申请；quilt.svg 因 skia 不解析其 CSS class，先内联 fill 后栅格化）。

## 依赖申请 / 接线说明
1. **外壳生命周期接线**：B0 的 PageBase.OnCreate/OnActivate 由外壳在挂页时调 ShellAttach，但 MainWindow.Navigate 目前直接 SetContent 不调。本页已在构造函数自启动数据加载（OnCreate 逻辑前置），OnActivate 做兜底，行为不依赖外壳接线。若外壳后续统一接 ShellAttach，本页无需改动。
2. **csproj 资源项**：通过 base64 内嵌规避，无需申请。若后续要求改回 AvaloniaResource（Assets/*.png 需重新生成常量，PNG 源已并入常量未保留）。
3. **命名空间解析坑（转告 B1/B5）**：namespace `TipCL.App.Pages.*` 下简单名 `Ui` 被解析成命名空间 `TipCL.App.Ui` 而非 `Ui` 类，须用别名 `using UiClass = TipCL.App.Ui.Ui;`（B2 已在 LibraryPage 同款注释）。本包两页与 LoaderIcons 已按此约定；LaunchPage 当前的 CS0234 应即此因。
