|---|---|---|---|---|

- **B1 的做法与证据**:`System.Text.Encoding.CodePages` 只是 ImageSharp 2.1.13 的**传递依赖**(全仓无直接 `PackageReference`),用 Costura `ExcludeAssemblies` 排除出单 exe。**不能用"全量用例全绿"证明它安全**(测试宿主是 net8.0、自带一份 CodePages),本轮改用更强的验证:把 compact exe **单独**放进一个目录(同目录**零个 `.dll`**),用纯反射夹具加载它并解真实**有损 VP8** WebP → `input=4880 B output=25428 B pngSignature=True`、**`codePagesLoaded = False`**、`RESULT=PASS`;同时 dump 确认 `TipCL.WebView2Loader.{x64,arm64,x86}.dll` 三条**仍在**(`|` 分隔符没把原有排除搞坏)。
- **未做的两条(维持 D-36 原判)**:
  1. **353 KB 图片降质**(`PremiumAssets/hero.jpg` 275,898 + 4 张预设壁纸 77,129)= 用户**可见的画质变化**,须先拿到"允许降质到什么程度"的结论并给逐图对照。

## 6 · 本轮抓到的隐蔽坑清单(长期价值最高的一节)

> 这 7 条都**不会**在"0 错 0 警 + 全绿"里暴露,建议维护者单独留意。

1. **生成物没被 `.gitignore` 覆盖,`git status` 长期挂脏 / 可能误 `git clean`**
   - `artifacts/`(布局验收截图,87 文件约 9.8 MB,备份见 `_tmp/backup/windos-artifacts.zip`);
   - `_wpf_run/` 与 `_wph_run/` —— **只差一个字母**,两套命名同时在用,所以两条都要忽略(`*_wpftmp.csproj` 同理);
   - `*_wpftmp.csproj` / `*.wpftmp.*` —— WPF 构建期临时工程文件,会出现且不被任何既有规则覆盖。
   已由 `8ba3997`、`8bc37bd` 补进 `.gitignore`(不改任何交付物)。
2. **⚠️ `.gz` 文件名的"最后一段"若恰好是区域代码,资源会被塞进附属程序集,主 exe 里没有**
   - 实例:`tipcl-plugin.d.`**`ts`**`.gz` 被 .NET SDK 判成区域 **`ts`(Tsonga)**,于是进了
     `obj\Release\net48\ts\TipCL.resources.dll` 而不是主 exe(diag 日志原话:「为文件"…"指定了区域性"ts"」、
     「获得了清单资源名称"TipCL.Resources.plugin_host.tipcl-plugin.d.gz"」),内嵌资源从 35 条掉到 **34** 条。
   - **构建 0 错 0 警、测试宿主也照常过 —— 只有漂移守卫用例能揭穿它。**
   - 修法:这些 `EmbeddedResource` 加 **`WithCulture="false"`**(它们本来就不是本地化资源)。
   - 同类风险名:`foo.de.gz` / `foo.fr.gz` / `foo.it.gz` / `foo.es.gz` / `foo.ja.gz` …
3. **Costura `ExcludeAssemblies` 的分隔符是 `|`,不是逗号**(XML **属性**形式;依据 Costura.Fody 6.0.0 自带 `Costura.Fody.xcf` schema:"delimited with **|**")。
   写成逗号会把整串当成**一个**程序集名 —— **既拿不到那 527 KB,还会把原有的 `WebView2Loader` 排除一并搞失效**。
4. **⚠️ 别把"exe 哈希变了"归因给构建目录 —— 真因是内嵌了 `1.1.0+<git commit sha>`**
   (本条先前记成"exe 字节与构建目录路径相关",已由 win-verify **自我推翻**,此处按更正后的结论记。)
   - **决定性实验**:**同一 commit 在不同目录构建,产物逐字节完全相同**;先前观测到的"两次构建差约 90 B"并非目录所致。
   - **真因**:SDK 的 SourceLink git 目标(`Microsoft.Build.Tasks.Git` 的 `InitializeSourceControlInformationFromSourceControlManager`)把
     `AssemblyInformationalVersion` 写成 `1.1.0+<完整 commit sha>`;两次构建的体积/哈希差异来自 4 段 ——
     PE `TimeDateStamp`、模块 `MVID`、以及该串的 **UTF-8 与 UTF-16 两种编码**。
   - **本仓自查**:`src\TipCL\bin\Release\net48\TipCL.exe` 里可直接搜到 `1.1.0+<构建时 HEAD 的 40 位 sha>`(本轮实测命中)。
   - **正确规则**:①**对账必须"同 commit 同批"**(换 commit 换哈希、体积基本不变);②同 commit 换目录**可复现**;
     ③**交付件必须对应最终 HEAD 的 commit,并记录其内嵌 `+sha`**。
5. **本机没有 PowerShell 7,且中文 `.ps1` 必须存成 UTF-8 带 BOM**:
   Windows PowerShell 5.1 按 ANSI(cp936)读**无 BOM** 的 UTF-8 脚本,中文字符串字面量会解析失败
   (`The string is missing the terminator`)。仓库现状:`tools/build-both.ps1` = UTF-8 **带 BOM**;
   `tools/dump-embedded-resources.ps1`、`_tmp/locks/build-lock.ps1` = **纯 ASCII**。新脚本二选一。
6. **本机沙箱下测试宿主建不了真实 `%TEMP%` 目录** ⇒ 直接跑全量会有约 **81 例假红**
   (`UnauthorizedAccessException`,出现在 `PageLayoutTests` / `LayoutWidgetTests` / `FileMemoryTests` 等,看着像代码坏了其实不是)。
   解法:把 TEMP/TMP 指到**工作区内**目录后再跑:
   `$env:TEMP='D:\项目\tipcl\_tmp\<某目录>'; $env:TMP=$env:TEMP; dotnet test tests\TipCL.Tests -c Release --no-build`
7. **"生成 `.gz`"与"改 csproj"必须同一段持锁时间内背靠背完成**:
   改造前 plugin-host 是**通配** `<EmbeddedResource Include="Resources\plugin-host\**\*" />`,**会匹配任何新增文件** ——
   只生成 `.gz` 而没改 csproj 的话,plugin-host 会**同时嵌入"原文 + .gz"两份,exe 反而涨约 158 KB**,
   而且会**静默污染别人的体积基线**(只看字节数看不出来)。
   另:改任何 Core 资源源文件后**必须重跑 `tools/pack-core-resources.ps1`**,否则内嵌的是旧内容(漂移守卫会红);
   `pack-core-resources.ps1 -Check` 可在构建前提前发现。
