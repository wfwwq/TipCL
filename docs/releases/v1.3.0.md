# TipCL v1.3.0 更新日志

> 面向玩家。写作时间 2026-11-28,提交范围 `v1.2.0..a9106de`(`release/v1.3` 共 277 条,其中 11-20 及以后的 210 条属于本版,前 67 条是 v1.2.0 那次的尾巴、已在 v1.2.0 的「修订」里写过,本文不重复)。

**一句话:v1.3 是「自定义界面重做 + 安全收紧」的一版 —— 布局的编辑界面整套重画(布局 v3),Linux 版一口气补齐大批真能干活的 AI 工具,同时把 MCP 接口、账号令牌、发布包校验这三处扎紧。**

## 布局 v3:编辑界面重做

- 编辑布局不再是页面底部一排挤在一起的文字按钮,而是内容区顶部一条工具条:左边写着「编辑「下载」页」,中间是「列表 / 网格」切换,右边是撤销、重做、「添加」、「重置本页」、「完成」,以及「⋯」里的「导出本页 / 导入到本页 / 整套布局与方案」。
- 页面上的区块换成灰色虚线框,块名**悬停**才出现,只有选中的块用主题色;自建组件显示你自己起的名字,不再冒出 `w_note1` 这种内部编号。
- 隐藏和删除分清:内置内容用眼睛图标藏着(还能在「添加」里找回来),自建组件用垃圾桶删掉(只摘本页的引用,组件本身还在),删错了 Ctrl+Z 撤销。
- 新增「添加」抽屉,从右侧滑出:上半是「本页已隐藏的内容」,点「显示」就回来;下半是组件库,点「添加」就加进来;加完页面会自动滚到新块并闪一下。
- 模式只剩「列表 / 网格」两种,自由画布退出界面;以前存成画布的页面会自动按网格排好,**存档不动**,你自己编辑一次之后才改写。
- 启动页也换了新版:主区域锁死不能拖(右上角会说明),右侧的组件区跟别的页面一样可以摆放、编辑。

<sub>依据:`git log v1.2.0..HEAD` 中 layout v3 相关 43 条提交(`8cad7d0` 任务书、`b609ef1` 令牌、`6277714`/`865b10e` 改名与默认、`248ba09`/`1f0de67` 编辑态与抽屉、`745dba3` 启动页 v3、`66bd970`/`177b77d`/`1a4848a` 两树合并)。</sub>

## 设置 → 布局:重排成五组

- **外观**:区块间距做成紧凑 / 标准 / 宽松三档,所有可以自定义的页面一起生效。
- **导航**:顶部页签变成一排可以拖动排序的标签,每个后面带眼睛图标(「设置」不能隐藏),改完标题栏立刻变;标题栏开关只剩「AI 按钮 / 主题切换 / 账号」,并注明隐藏 AI 按钮后仍可按 Ctrl+K 打开。
- **页面**:缩略图卡片网格,每张标「默认」或「已自定义」,点「编辑」直达那一页,右上角有「全部恢复默认」;以前那 12 个一模一样的「自定义布局...」按钮没有了。
- **方案**:卡片列出所有方案,正在用的有描边、不能删;AI 改布局前自动存的那份显示成「AI 改布局前」;卡片菜单能重命名 / 复制一份 / 删除。
- **高级**(默认折叠,标着「一般不需要动」):分栏宽度只剩一句说明 + 「全部复位」;网页和按钮组件给了一个总开关(默认关,导入的布局里带这类组件仍然默认关闭,要你逐个打开);布局 JSON 挪进**独立的编辑器窗口**,页面上不再常驻一个 JSON 框。

<sub>依据:同批 43 条中的设置页与令牌部分 6 条(`b609ef1`、`cb8ad4c`、`55f7f88`、`8722bd2`、`8f656e8`、`1f0de67`),规格见 `windos/GOAL-layout-v3.md` §5.4。</sub>

## 各页默认布局与区块命名

- 联机、游戏时长、Java、启动页下方内容区换上了新的默认网格 —— 以前要自己摆的位置,现在打开就顺眼;游戏时长、Java 的白话说明默认收起。

## 布局的手感与数据安全

- 拖块更跟手:浮起跟手、落点占位框、让位动画、6px 滞回防抖、拖到边缘自动滚动;Linux 版补齐了 Windows 早就有的这套手感。
- 铺面细节一起修了:滚动条不再被裁切、改窗口大小不再重新排版、抓起来不再跳、拖拽预览按真实尺寸裁剪。
- 布局文件损坏前会**强制留一份备份**,备份不了就拒绝写入 —— 不会因为一个坏文件把你的布局一起写没。
- 导入别人的布局时,里面的网页 / 按钮组件一律默认关闭,要你自己逐个打开。
- AI 排版改不了的画布模式会按网格处理并回一句提示;AI 动布局之前先存一份「AI 改布局前」方案,随时能回退。

<sub>依据:`4277a02`(拖动跟手 / 删块清方案引用 / 危险组件默认关)与 R33 审计里布局手感相关 6 条(`3000b61`、`bf84904`、`ab3d49e`、`94f2ff6`、`c0551f7`、`6d7bdf5`)。</sub>

## AI 助手(Linux 版):排错、卡顿、账号、联机

> 这一批是 **Linux 版**这版新补上的(README 的「AI 助手」表里标「仅 Linux 版」的那几行);本版提交里没有任何一条 AI 工具改动落在 Windows 树,Windows 版能力不变。

- **排错**:直接读最新日志和崩溃报告,也能列目录、读文件、写文件、打开所在文件夹,不用自己翻数据目录。
- **卡顿与存档**:看硬件、诊断卡顿、按实例调内存和 GC;列存档、备份、列备份、回滚(回滚前先把当前状态再备份一次)。
- **账号 / 皮肤 / 联机 / 排版**:列账号、加离线账号、切账号、把图片设成皮肤、开内置联机、读和改布局。
- **启动前预检**:点「启动」会先查 Java、前置模组、加载器和内存,发现问题给你「交给 AI 一键修复」或「仍然启动」(设置里可关)。
- **服务器与光影**:查服务器延迟、在线人数和版本(支持 `_minecraft._tcp` 的 SRV 记录),增删游戏内多人列表;按显卡和内存分低 / 中 / 高配推荐光影和资源包。
- **诊断报告**:把排查过程、日志片段、模组清单和硬件摘要导出成一份报告,自动打码账号令牌和用户名。

<sub>依据:AI 各包中新增工具提交 12 条(`32432e1` 日志与文件、`ab5b4eb` 卡顿与存档、`98ac340` 账号皮肤联机排版、`5de8306`/`03e4410` 预检与诊断报告、`9cf9dc5` SRV),口径见 `README.md`「AI 助手」表里标「仅 Linux 版」的那几行。</sub>

## AI 助手(Linux 版):整合包、内容创作、模组开发

- **整合包**:按主题出候选清单(Modrinth 与 CurseForge,每项带理由、前置、冲突提示),确认后建实例、后台整批安装并逐项显示进度,最后导出 mrpack 或 CurseForge 整合包;导出前查分发许可,禁止分发的模组会拒绝导出,来源不明的 jar 默认不打包。
- **内容创作**:生成数据包、资源包,装了 KubeJS 也能写脚本;按 MC 版本对照 `pack_format` 并校验格式,引用的 ID 命名空间不是 minecraft 也不是已装模组时会提醒,写完提示你 `/reload` 或 F3+T。
- **实例升级**:「把这个整合包升到 1.21」—— 逐个查模组有没有目标版本,列出可升级 / 缺失 / 替代建议,确认后复制成新实例再升,不动原实例。
- **自己写模组**:外部编程工具(Claude Code、Cursor 等)经 MCP 把 TipCL 当测试环境 —— 建测试实例、装本地 jar、撤回、试启动并读崩溃报告、查任务状态;试启动只关自己拉起的那个游戏进程,任务记录重启后还能查。
- **MCP Server**:Linux 版从这版起也有本机 MCP Server(`127.0.0.1:25585/mcp`),协议、配置键与 Windows 一致,默认关闭,设置页里能开关还能改端口;AI 页有「MCP 已开启 · 最近外部调用」状态条。

<sub>依据:`0c8e9fd`、`fb4c067`(整合包)、`0c4cac1`、`eb25b1c`(数据包 / 资源包 / KubeJS)、`5de8306`(实例升级)、`d6fd8af`、`3a484b8`(模组开发测试环境)、`27b5694`(Linux MCP Server)。</sub>

## AI 引擎(Linux 版)与稳定性

- 外部 agent 发起的写操作一律弹确认卡,不给「以后都允许」(哪怕权限档是全自动);确认时主窗口自动置前,120 秒没人点按拒绝处理。
- 只读工具改成并行执行,结果与事件仍按原顺序回填,一个工具出错不影响同轮其它工具;参数坏掉的调用不会再拿空参数照跑。
- 工具前后钩子和权限规则补齐:能按参数、按作用的实例判定,和 Windows 同一套。
- 长对话不再越用越慢:AI 会话与响应读完即释放(以前每轮都漏一点),流中断重试也不会把同一段文本写两遍。
- 原地升级撤回只删这次新装的版本目录(按执行前后的目录差集),认得出 OptiFine / Forge 安装器的各种目录形态,不会误删你原来的版本。
- 启动内存 / GC 的实际生效值只算一处:设置里填的、启动前预检报的、AI 工具读到的,现在是同一个数。

<sub>依据:AI 各包中引擎与稳定性提交 13 条(`1df5b76`、`cfd7401`、`27b5694`、`d6fd8af`、`78f4430`、`9fe8b1f`、`80961a8`、`0c7fff8`、`d7a1dec`、`e750ba8`、`98b4800`、`6493474`、`2f9de51`)。</sub>

## 安全加固:MCP Server 接口

- MCP 现在只收 JSON:不是 `application/json` 的 POST 直接拒掉 —— 以前网页发一个「简单请求」就能绕开跨域预检,直接打到 `tools/call` 上。
- `Origin: null` 和非本机 `Host` 一律拒绝:挡住 sandbox iframe / `file://` / `data:` 页面借浏览器调本机接口,也挡住 DNS 重绑定。
- Windows 版外部写操作**也开始弹确认**,和 Linux 版对齐:没有确认界面、点拒绝、或者 120 秒没人点,统一按拒绝(`permission_denied`)处理。
- AI 读写文件的路径守卫同步收紧:显式拒绝 `nul` / `con.txt` / `aux` 这类设备名;允许目录自带的 8.3 短名(`RUNNER~1`)不再被当成「用户绕守卫」而误拒。

<sub>依据:`3e868b6`(SEC-MCP-1 两版 + SEC-MCP-2 Windows 确认)、`e42697e`/`1ec02c1`(ai-fs 路径守卫与回归用例)、`1df5b76`(确认闸门),对外口径同 `README.md`「MCP Server」平台口径段。</sub>

## Linux 版:微软账号不用每次重启都重登

- 令牌现在会真的存下来:优先存进系统密钥环(GNOME Keyring / KWallet,经 `secret-tool`,密码只走 stdin);系统没有密钥环,就存到数据目录下权限 **600** 的 `secrets.json`;`accounts.json` 也收紧到 600。
- 只想用文件?设 `TIPCL_SECRET_STORE=file` 强制走文件那条路。
- 以前这条链是空的:凭据库在非 Windows 上从没被赋值,只能写一个 `unavailable:` 占位,于是每次重启都要求你重新登录 —— 这一版是真修好了(往返、600 权限、损坏文件、回落都有测试钉住)。

<sub>依据:`215522a`(SEC-AUTH-1)、`README.md`「安全说明」第三条。</sub>

## Linux 版:发布包带校验文件

- 从这版起,`TipCL-linux-x64.AppImage` 与 `tipcl_<版本>_amd64.deb` 都附同名 `.sha256` 附件(格式同 Windows:一行 64 位十六进制),下载后 `sha256sum` 对一下就知道是不是原件。
- v1.2.0 及更早的 Linux 包没有这个附件,那时的 SHA-256 只出现在 Actions 日志里。
- `.deb` 不进自动更新清单(装到 `/opt` 这种形态只下载、由你手动安装);两份清单仍然只有 `version` / `notes` / `url` / `sha256` 四个字段,客户端只显示 `notes` 那一串。

<sub>依据:`a9106de`(release.yml 给 AppImage 与 .deb 各附 .sha256);清单字段口径见 `docs/RELEASE-CHECKLIST.md` §4。</sub>

## Linux 版:正确性修补

- 显卡与显存认得更准:接上 `nvidia-smi`(含 WSL2 下的占位设备)、把 Basic Render Driver 算作核显、合并同一张卡的多次上报 —— 推荐光影不再乱猜。
- 从压缩包装出来的 Java 现在有执行位(以前在 Linux 上装完点了没反应),压缩包也按真实后缀命名(以前 Zulu / Microsoft 的包会被当成错的格式)。
- 点微软登录会用系统浏览器打开(Linux `xdg-open`、macOS `open`),不再等一个打不开的内嵌页。
- 一批以前点了没反应的按钮接上了:智能推荐、服务器导入导出、账号登录入口、主题包导入导出。
- 前置模组装不上不再静默失败,任务卡上能看到是哪一条、为什么;清理失败也会计数落地。
- 顺手修掉的崩溃:AI 页「清空 / 新对话」重复挂空态、启动按钮连点重复启动、插件区块外壳在同一控件上挂两处。

<sub>依据:`1154704`(显卡与浏览器打开)、`d1a8754`/`ac01864`(Java 执行位与后缀)、`0fd7dc7`(假按钮接线)、`aad6e72`(前置依赖不再静默)、`1ed7c0b`/`0323159`/`afd97dc`(崩溃与重复启动);对应 E 段 WSL2 真机复核 `73fd39c`、`40cf8a4`。</sub>

## Windows 版
