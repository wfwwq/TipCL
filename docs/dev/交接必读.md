## 本机环境与构建前置(跑 build / test 前必读)

### 1. `dotnet test` 报 `hostfxr.dll could not be found` 时:先覆盖 `DOTNET_ROOT`

- **症状**:`dotnet test` 起 testhost 失败 —— `Testhost process ... exited with error: A fatal error occurred. The required library hostfxr.dll could not be found.`(诊断页也写作 `missing_runtime`)。**任务书 §1 曾把它误判为「testhost.exe 自身启动失败」,并据此归因到中文目录 / worktree 路径编码,均不成立。**
- **根因**:环境变量 `DOTNET_ROOT` 指向了一个**没有运行时的目录**。本机历史上 User 级 `DOTNET_ROOT` = `C:\Users\Administrator\.dotnet`,该目录只有遥测/哨兵文件(`*Sentinel`、`TelemetryStorageService`、`sdk-advertising`),**没有 `host\fxr`,也没有 shared 运行时**。testhost 是独立进程,靠该变量定位运行时 → 找不到 `hostfxr.dll`。真实运行时在 `C:\Program Files\dotnet`(`host\fxr` = `8.0.34` / `9.0.23`;SDK `9.0.321`);Machine 级未设置该变量。
- **解法**:在该条命令**前面**加上覆盖(进程级,**不改本机设置**):

  ```powershell
  $env:DOTNET_ROOT='C:\Program Files\dotnet'
  dotnet test tests/TipCL.Tests/TipCL.Tests.csproj -c Release --nologo
  ```

  ⚠️ **每个 `pwsh` 调用都是独立进程**,`$env:DOTNET_ROOT` 必须写在**同一条命令**里才生效(分两次调用无效)。
- **状态说明**:User 级已在 **2026-11-28** 修正为 `C:\Program Files\dotnet`,但**已在运行的会话不生效**(子进程继承的是启动时的旧值)—— 实测 2026-11-28 当天,注册表已是新值而当前会话读到的仍是旧值,不带覆盖直接跑 `dotnet test` 依旧 `missing_runtime` 失败。**要么新开会话,要么继续用上面的进程级覆盖。**
- **CI 环境正常**,`DOTNET_ROOT` 由 hosted runner 正确设置 —— **不要**把上面这行覆盖写进 `.github/workflows/*.yml`。

### 2. Windows 树(`windos/`)**本机可以编译**

net48 参照程序集**不需要**装 .NET Framework 4.8 Developer Pack(那需要管理员权限,会弹 UAC):它由 `windos/src/TipCL/TipCL.csproj:53` 的 `Microsoft.NETFramework.ReferenceAssemblies` **1.0.3** NuGet 包提供,本地 NuGet 缓存已具备。机器级 `C:\Program Files (x86)\Reference Assemblies\Microsoft\Framework\.NETFramework\v4.8` 目录**确实不存在,但不影响编译**。实测(`2026-11-28`):

