## A. Windows / MCP:用真客户端调一次 `enable_mod`

### 前置

1. 装 v1.3 的 `TipCL.exe` 并启动。
2. 打开 MCP Server(默认关闭):**设置 → AI 助手 → MCP Server**;记下地址 `http://127.0.0.1:25585/mcp`。
3. 在真客户端里接上(二选一):
   - Claude Code:`claude mcp add --transport http tipcl http://127.0.0.1:25585/mcp`
   - Cursor / Claude Desktop(只吃 stdio):`npx mcp-remote http://127.0.0.1:25585/mcp`

### 三条判定

| # | 怎么做 | 怎么算过 |
|---|---|---|
| **1 弹窗** | 让客户端调 `enable_mod`(例如「把 a.jar 启用」) | TipCL 主窗口**自动置前**并弹确认框,标题「允许外部写操作?」,正文含工具名与参数(超 400 字的参数会截断加 `...`);点「允许」→ 工具真的执行,客户端拿到结果 |
| **2 拒绝** | 再调一次,这次点「拒绝」 | 客户端收到 `permission_denied`,`Tools.RunTool` 那一步没发生 —— 去实例的 `mods/` 看,`.jar.disabled` **没有**被改回 `.jar` |
| **3 120 秒超时** | 再调一次,弹窗出来后**什么都不点**,等满 120 秒 | 客户端收到 `permission_denied`(原因里含「120 秒内没有确认」)。**此时再点「允许」不会补执行** —— 这一步就是确认超时是 fail-closed |

> 判定 3 的「点了也不算数」是设计如此:超时那一刻已经返回拒绝,弹窗只是还没关。如果你觉得这个残留弹窗别扭,记进反馈,别当 bug 修 —— 它不是安全洞。

### 顺手验(可选,一条命令一条)

```bash
# GET 不是 POST → 405
curl -i http://127.0.0.1:25585/mcp
# 简单请求(text/plain)不触发 CORS 预检 → 必须被 415 挡下
curl -i -X POST http://127.0.0.1:25585/mcp -H "Content-Type: text/plain" -d '{}'
# sandbox iframe / file:// 页面的 Origin → 403
curl -i -X POST http://127.0.0.1:25585/mcp -H "Content-Type: application/json" -H "Origin: null" -d '{}'
# DNS rebinding:Host 不是环回名 → 403
curl -i -X POST http://127.0.0.1:25585/mcp -H "Content-Type: application/json" -H "Host: evil.example" -d '{}'
```

### 没过时看哪里

- 没弹窗:确认 `BridgeHost` 里 `McpConfirmUi.Install()` 跑过(它在 `McpServer.StartIfEnabled` 之前);`Application.Current` 为 null 时会**直接拒绝**而不是放行。
- 放行得太干脆:检查是不是绕过 MCP 走了别的路径 —— 闸门在 `McpServer.CallTool` 里,按 `Tools.IsWriteTool` 分类。

## B. Linux:微软账号重启后不用重登

### 前置

一台有桌面会话的 Linux,跑 v1.3 的 `TipCL-linux-x64.AppImage`。

### 五步

1. **首次登录**:账号 → 添加微软账号 → 浏览器里登录成功 → 账号出现在列表里且为当前账号。
2. **看令牌落在哪**(二选一,取决于有没有密钥环):
   - 有密钥环:`secret-tool lookup service tipcl` 能查到,或 GNOME 钥匙串里出现 TipCL 条目。
   - 没有密钥环:数据目录下出现 `secrets.json`,**权限必须是 600**:
     ```bash
     stat -c '%a %n' secrets.json accounts.json   # 两个都该是 600
     ```
3. **重启免登录**:完全退出启动器 → 重新打开 → **不应**再要求登录,且能直接用这个账号启动游戏。
4. **强制文件模式也免登录**:
   ```bash
   TIPCL_SECRET_STORE=file ./TipCL-linux-x64.AppImage
   ```
   重启后同样免登录(说明回落路径完整,不只是密钥环那条能用)。
5. **反向验证(可选但推荐)**:删掉 `secrets.json` 和密钥环条目后重启 → **应该**提示重新登录。如果还能免登录,说明读的不是真存储,这条要当 bug 追。

### 没过时看哪里

- 重启又要求登录:先看是不是每次都在走「写失败 → 回落」;`PlatformServices.SecretStore` 为 null 时会写 `unavailable:` 前缀 —— 日志里搜 `系统密钥环写入失败`。
- 权限不是 600:`FileSecretStore.Save` 是先建空文件 → 收紧权限 → 写内容 → 原子替换;若目录本身不可写会走 warn 日志(收紧失败只记日志,不阻断,这是已知的小瑕疵)。
