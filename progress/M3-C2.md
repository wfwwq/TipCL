# progress/M3-C2 · 打包交付（2026-11-08）

## 做了什么

1. **版本**：`src/TipCL.App/TipCL.App.csproj` 的 `<Version>` 由 `0.1.0-m1` 升为 `0.1.0-m3`（任务书允许的唯一 src 改动，单独说明）。注意 `TipCL.Core.csproj` 仍是 `0.1.0-m1` 且 `tests/SmokeTests` 断言 Core 版本 = m1，均非本包地盘未动；若 C3 要统一升版需连测试一起改。
2. **发布参数验证**（Windows + SDK 10.0.403 交叉编译）：
   - linux-x64 与 win-x64 self-contained 单文件均发布成功。
   - 关键参数：`-p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true`。不加 `IncludeNativeLibrariesForSelfExtract` 时 Skia/HarfBuzz 的 .so 会散在单文件旁（实测 libSkiaSharp.so 8.9 MB + libHarfBuzzSharp.so 2.4 MB），加了才真单文件。
   - **实测体积**：linux-x64 单文件 44,571,174 B（42.5 MB）；win-x64 45,416,357 B（43.3 MB）。未压缩对照：linux-x64 72 MB + 11 MB 原生库。
3. **Trimming 取舍：不 trim**。试 `-p:PublishTrimmed=true -p:TrimMode=partial`：编译通过但产生成片 IL2026（Core 的 System.Text.Json 反射序列化：`Layout/PageBlock.cs`、`Layout/PageLayoutStore.cs`、`Launcher/Sync/PhoneLink.cs`）与 IL2104（Avalonia.DesignerSupport）。trim 后运行时行为本机无法验证（Linux 产物不能在 Windows 跑），M3 交付确定优先。未来瘦身路径：Core JSON 迁 `JsonSerializerContext` source-gen 后再评估。
4. **打包脚本**：
   - `tools/package.ps1`（Windows）：双端 publish → `dist/TipCL-linux-x64/TipCL.App` + `dist/TipCL-win-x64/TipCL.App.exe`（剔除 pdb）→ 双 zip → win-x64 产物 `--smoke` 门禁。已端到端实跑验证（见下）。
   - `tools/package.sh`（Linux）：同源参数 publish + AppImage AppDir 组装（AppRun/tipcl.desktop/usr/bin/TipCL/hicolor 图标），装有 linuxdeploy 直接出 `.AppImage`，没装打印现成命令；`bash -n` 语法验证通过。**未在 Linux 真机执行**（本机无 Linux 环境）。
5. **AppImage 结构**：`tools/AppImage/tipcl.desktop`（Exec=TipCL、Categories=Game）、`tools/AppImage/tipcl.png`（256×256，按主题令牌 C.Accent #2E9B6B 圆角方块 + 白"T"，System.Drawing 生成，视觉已人工核对）。
6. **交付文档**：`docs/DELIVERY.md`（交付物清单、体积、运行方式、双端冒烟矩阵七项、已知限制）。
7. **win-x64 产物冒烟实跑**：`dist/win-x64/TipCL.App.exe --smoke` 退出码 0，smoke.png 751,793 B，人工核对正常。
