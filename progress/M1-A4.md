# M1-A4 · Core 业务复用层 — 完成报告

## 做了什么

把 Windows 版（反编译还原）`src/TipCL/Core/` 中可跨平台的业务代码**原样复制**进 `src/TipCL.Core/`，共 **100 个 .cs（约 23,300 行，含 A1 的 CoreInfo.cs 占位与本次新增 Tests/）**，搬运源文件 97 个。命名空间 Windows 版本本就是 `TipCL.Core / TipCL.Core.Launcher`，与 Linux 工程一致，**零命名空间改动**；业务逻辑零改动。

`dotnet build src/TipCL.Core -c Release` → **0 错误 0 警告**（Windows 11 + SDK 10.0.403）。

- `TipCL.Core.csproj`：net8.0，无第三方包（JSON 用自研 PyJson，网络用 BCL System.Net.Http），保留 A1 的 `InternalsVisibleTo TipCL.Tests`。
- Win32/DPAPI/注册表：源码本身已是跨平台写法——DllImport 只出现在 `Utils.cs`（RtlGetVersion/VolumePathName）、`VersionSettings.cs`（symlink/junction）、`Auth.cs`（CryptProtectData）三处，且**所有调用点均由 `Utils.IS_WINDOWS` 运行时守卫并带 Linux 分支**（如 Auth 令牌在 Linux 明确提示"需重新登录"）。故无需条件编译改写，行为安全：Linux 上不会触发这些调用。
- 每个搬运文件第 1 行注明来源路径（`// 来源: Windows 版参考仓库 src/TipCL/Core/...`）。
- 新增 `Tests/CoreReuseSmokeTests.cs`（internal，不依赖 xunit，`RunAll()` 自证入口）：PyJson 往返、Config 默认值、Instances 名称归一、Installer._mc_tuple、Java.PLATFORM_KEY 共 5 例；M1-A5 测试工程可直接翻译成 [Fact] 或引用 `RunAll()`。

## 遗留与风险

1. **Runtime 行为未实测**：编译自证通过，但网络下载/账号刷新/Java 探测的真机行为留待 M3 Linux 实测；`IS_WINDOWS` 守卫分支理论上完整（源码本身按跨平台编写）。
2. **Java.cs 的 Windows 注册表探测**：grep 无 Registry 命中（走目录扫描+PATH），但 `_JAVA_HINTS` 路径猜测表以 Windows 目录为主，Linux 提示路径可能不全——M3 补 `~/.sdkman` 等常见 Linux JDK 路径。
3. **McLauncher/Preflight 未搬**导致 `McLauncher.cs` 引用链（LaunchFlow、GameProcess）缺席，`dotnet run` 启动 Minecraft 属 M3；Catalog/Installer 已可独立支撑下载安装逻辑。
4. CoreInfo.cs 仍为 A1 占位类型，未删（避免影响可能引用它的 App 骨架代码）。
